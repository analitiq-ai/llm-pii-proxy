## Executive Summary

The spec is tightly scoped: P1 is a local scrubber, and P2 is a confidential second pass that can be shipped
separately. Fail-closed, no-logging, and pseudonymisation-not-anonymisation are stated explicitly. The plan
found the real hazard early (thinking-signature prefix checks) and put a go/no-go spike in front of
implementation.

Two design defects must be fixed before tasks:
- **The placeholder grammar is not self-delimiting.** A token followed by a digit restores to the wrong value,
  which corrupts files on disk.
- **The leaf cache has a race.** Concurrent requests from one session (parallel subagents send identical system
  and CLAUDE.md leaves) can each produce different bytes for the same leaf, and that breaks the byte-identical
  re-send guarantee the design depends on.

Separately, nobody has compared building this against adopting one of several existing open-source proxies that
do the same job. That question should be answered before S1 spends effort.

## Engineering Lens Findings 🔬

### Architecture Soundness
| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E1 | 🎯 | **Leaf cache race.** Two in-flight requests in one session (parallel subagents share system-prompt and CLAUDE.md leaves) can both miss the cache for the same raw leaf. With the confidential pass on, which isn't deterministic, they can produce different bytes, and one of them is then sent with bytes the cache doesn't hold. That breaks R3's byte-identical guarantee for that agent. Separately, "cache only after the whole request succeeds" widens the window. | **Single-flight per leaf hash**: the first scrub of a leaf owns a future, and concurrent requests await it. Cache a leaf as soon as *that leaf* scrubs successfully. Once computed, its bytes are fixed whether or not the request is later forwarded. Never cache a failed leaf. Update data-model.md (Leaf cache) and confidential-detection.md (Response handling, last paragraph). |
| E2 | 🎯 | **Placeholder grammar is not self-delimiting.** The greedy ordinal means a token directly followed by a digit is mis-parsed. Example: PERSON value `Al` inside `Al2O3` becomes `PII_PERSON_12O3`, which restores as `PII_PERSON_12` (wrong value or unissued) and corrupts the file. The known-value stage also replaces values with no word-boundary rule, so short names get replaced inside longer words. | Use a **fixed-width ordinal** `PII_<CATEGORY>_<4 digits>` (e.g. `PII_EMAIL_0001`), which is unambiguous whatever follows. Fail closed past 9999 per category. Stage 2 replaces a known value only where it isn't adjacent to a word character at either word-character edge. Update placeholder-format.md (grammar, holdback) and data-model.md (Placeholder). |
